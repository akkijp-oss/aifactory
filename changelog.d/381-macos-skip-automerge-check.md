### Fixed
- **A pull-worker (macOS / Windows / Linux) project without `auto_merge` no longer fails at startup because the workflow now contains the `automerge` step (ADR-0042).** The macOS backend validated every `code:` step name before the run started and rejected `pr-automerge.sh` as unsupported, even though the runner skips that step for projects that have no `auto_merge`; every asura run died with `unsupported pull-worker code steps: pr-automerge.sh` before taking the guest. The check now ignores `pr-automerge.sh` when the project has no `auto_merge`. Projects that do set `auto_merge` on a pull worker are still refused up front, because `pr-automerge.sh` drives `sandbox ssh` and has no pull-worker implementation yet
