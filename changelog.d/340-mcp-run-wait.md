### Added
- **MCP から run の工程遷移を 1 呼び出しで待てるようになった**。`run_wait(name, until, timeout_s)`（既定 60 秒・上限 300 秒）が `state.json` を読み直し、工程が変わった瞬間（`until: step`、既定）か run が終わった瞬間（`until: result`）に `{changed, status, step, ok, next, result, pr_url, gate_fails, gates, reason, current, history, elapsed_s}` を返す。ログ本文は含まないので、ログを grep して「今どの工程か」を組み立てなくてよい（agent 自身の出力に `result: success` が混ざるため、ログ本文からの終了判定は誤りやすかった）。`timeout_s` に達したら `changed: false` のまま返るので繰り返し呼ぶ。`job_wait` と同じく待っている間も他のツールは即応する（ADR-0051）
- **`run_show` に `progress` が付いた**。run 全体の経過秒、工程ごとの経過秒（`history[].elapsed_s`）、今の工程（`current: {step, kind, since, elapsed_s}`）、直近のゲートの PASS / FAIL / INFO 一覧（`gates`）が読める。`code-gates-N.log` を開かなくてもゲートの状態が分かる。経過秒は前の工程が終わった時刻からの差なので、`--from` で再開した run や VM の空き待ちを挟んだ run では工程の外の時間が混ざる（導けないときは `null`）
