### Added
- **Console run page: the *Definition:* line now explains what each step does.** Step ids (`implement`, `gates`, `sync`, `resolve`, `pr`, …) were shown bare, so an operator had to know the workflow yml to tell what a step was doing or why a run went back to `implement`. A *What each step does* fold under the line lists every step with a one-line description (kept in `strings.js` as `stepDesc.*`, checked against every step id in `workflow/kit/workflows/` by `test_strings.py`), the workflow's own `brief`, the files it reads and writes, and where a failure sends it back to and after how many loops it waits for a human. Hovering a step in the line shows the same description. Open folds now survive the 5-second refresh of a running run
