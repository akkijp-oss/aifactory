### Fixed
- **The runner merges the latest base right before it opens the PR, and sends a conflict back to the implementer instead of to a human (ADR-0031).** A run took `origin/<base>` at `sandbox take` and never looked at base again, so merging one parallel run's PR made every later PR come out CONFLICTING — seven of them in one afternoon, all conflicting in the same places. Every workflow that ends in a PR (bug / feature / hotfix / docs / chore) now has a `sync` step (`code: sync-base`, built into the runner, so all backends share one implementation) in front of `pr`: it fetches base, merges it when it is not already in, and on a conflict records the conflicting file names, runs `git merge --abort` so the agent never receives a conflicted tree, and goes back to a new `resolve` step — the implementer redoing the merge with both sides' intent kept. A human is only involved when that fails twice; the reason then lands in `state.json`'s `error` and in the ticket's note. After the merge the runner also checks `docs/adr/` for duplicate numbers, which git treats as a clean merge because they are separate files. Gates are not re-run when there was no conflict. The Windows worker skips the step (its shell is PowerShell)

### Changed
- **A user-visible change is now recorded in `changelog.d/<ticket>-<slug>.md`, not in `CHANGELOG.md` directly.** Every run appended to the same line under `## [Unreleased]`, which guaranteed a conflict between parallel PRs; one file per entry cannot conflict. `bin/changelog-release collect` merges them into `## [Unreleased]` by heading at release time and deletes them, `--dry-run` previews it, and `bin/changelog-release check --base <ref>` (wired into the aifactory gates) fails a branch that edits `CHANGELOG.md` without also removing `changelog.d` files. Entries already in `## [Unreleased]` stay where they are
