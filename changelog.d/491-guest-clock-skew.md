### Fixed
- **sandbox / runner: ゲストの時計がずれたまま工程を始めないようにした**。プール VM は RAM 込みの snapshot を巻き戻して貸すので、復元直後のゲストは snapshot を取った時刻から時計が再開し、NTP の次のポーリング（既定では最大 34 分）まで数日ずれたまま走っていた。その間に付いたコミットの author date と agent が書く ADR の日付が嘘になり、`git log --since` や `--diff-filter=A` が取りこぼす（実測で 6 日 17 時間）。`sandbox take` / `sandbox reset` が env を注入する前にゲストの時計を制御系へ合わせるようにし（`[clock] guest offset …` を出力）、runner は貸出直後に必ず測って許容（既定 120 秒、`AIFACTORY_CLOCK_TOLERANCE_S`）を超えていれば工程を 1 つも始めずに止める。止まった run はチケットが `blocked` になり、note に「`sandbox reset <id>` で巻き戻してから回し直す」と入る。測った値は実行記録の `clock_offset_s` に残る。ベーステンプレートは次に焼き直した分から NTP のポーリング間隔が最大 64 秒になる。
