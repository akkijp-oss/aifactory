# console の UX と文言の約束（1 ページ）

Web コンソールの画面と日本語文言を、個人のセンスではなく約束で揃えるための 1 枚。一般論の正本は `../docs/ui-ux-writing-guide.md`、判断の記録は `../docs/adr/0019-console-ux-friction-and-strings.md`。文言は全部 `static/strings.js`（`T`）に置き、`tests/test_strings.py` がこの約束を機械的に検査する。

## 人格

**有能で落ち着いた工場の運転員**。何が起きたか・次に何をすればよいかを短く言う。感嘆符・絵文字・感謝・装飾は使わない。

## 4 軸の表（機能ごとの設計）

| 操作 | ジョブ（誰が・いつ・何のため） | 頻度 | 可逆性と影響 | 操作直後の一手 | 設計 |
|---|---|---|---|---|---|
| ボードを見る | 運転員が、今どこまで進んだか知る | 毎日・何度も | 読むだけ | 動いている run へ | 最初の画面。5 秒更新。`g b`。PJ の選択は帯・列・動いている run に効く（絞り込みはサーバー側。`overview?pj=` で上限を掛ける前に絞り、あふれた run は「ほか n 件」で実行記録へ送る）。**左ナビのバッジは全 PJ**（画面をまたぐ数字なので PJ に連動させない）。対象範囲は帯の上の 1 行とバッジの `title` で言う |
| 動いている run を追う | 工程が正しく進んでいるか見る | run 中は何度も | 読むだけ | — | ボードの「実行中」から 1 クリック。実行中の工程のログを自動で開く。「定義:」の工程の並びには、工程ごとの説明を折りたたみ（各工程が何をするか）とホバーで添える。説明は id ごとの定型（strings.js の stepDesc）+ yml の brief / inputs / outputs / on_fail |
| 止まった run / 終わった run を確かめる | 運転員が、何が終わり・どこで止まり・どれを読めばよいかを知る | run が終わるたび | 読むだけ | 理由のファイルを開く / チケットを開く | 冒頭に「結果」パネル（結果の 1 文、赤いゲート、理由を読む / 報告を読む / チケットを開く）。導けない理由は「記録にありません」と出す。ファイルは目的別に 3 段（成果物 / 工程のログ / その他は畳む）。**runner が居なくなった run は「中断」**（脈は打たせない）: 終わったジョブの日時・状態・終了コードを添え、ジョブを開く / sandbox を見るを出す。VM が貸出中のままならそれも言う。準備段階（take）で失敗した run は「記録にありません」ではなくエラーの要約を出す。記録が欠けているだけの run を「v0」と呼ばない（読めない state.json はそう言う） |
| 過去のチケットを探す | 運転員が、前の依頼や直し方をブラウザーから思い出す | 週に数回 | 読むだけ | チケットを開く | チケットの一覧（`#/tickets`）。番号（前方一致）・題名（部分一致）・PJ・状態の AND で絞る。件数は「{n} 件（全 {m} 件）」、0 件のときは何を緩めるかを言う。条件は URL のクエリに持つので、詳細から「戻る」で同じ絞り込みに戻る。ボードの完了列は 15 件のままにして、あふれた分はこの画面へ送る |
| 起票する | 依頼を 1 枚のチケットにする | 毎日 | 可逆（完了・未着手に戻すで片付く） | できたチケットを開く | 起票画面。確認なし。ジョブが終わると「チケットを開く」を出す。**下書きは画面往復・再読み込み・戻るで残る**（sessionStorage。同じタブの中だけで、タブを閉じると消える）。破棄は明示操作（「下書きを捨てる」+ トーストの「元に戻す」）。送信できたときだけ、そのパネルの下書きを消す。離脱の警告は出さない。**PJ を選ぶと project.yml の有無をバッジの文字と本文で出す**（準備不足でも起票は止めない。sandbox 画面への導線を添える）。**2 方式の違い・登録で起きること・実行が始まる時点を画面の中で言う**（左は文章を LLM が整える、右はそのまま登録する。末尾で「起票しただけでは実行は始まりません」と言い、チケットの「実行する」とボードの「配車する」へ導く）。**種別の用途は `strings.js` の `kind.*`**（「いつ選ぶか」を利用者の言葉で。workflow yml の `description` は未知の種別の保険）。**本文の書き方は雛形をプレースホルダーで出す**（`label.bodyPlaceholder`。## 背景 と ## 完了条件 の箇条書き） |
| 添付する | 運転員が、画面や資料を実物でチケットに渡す | 毎日 | 可逆（消せる） | 一覧にサムネイルが増える | 起票画面の両パネルとチケット画面に同じ落とす領域（ドラッグ＆ドロップと選択の両方）。確認なし。選んだファイルは**下書きに残らない**ので、その旨を助言に書く。画像はサムネイル、他はダウンロードのリンク。上限と「トークン・鍵は添付しない」を助言に添える。起票と同時の添付が失敗しても、できたチケットの画面へ進み「起票はできた・添付し直せる」と言う |
| 添付を消す | 要らない添付を片付ける | 月に数回 | 不可逆（ファイルが消える）・影響は 1 件 | 一覧から消える | ダイアログ + 危険色。影響がその 1 件に閉じるので**名前の入力までは求めない**（VM の返却・ジョブの停止との差） |
| 配車する | 未着手を runner に回す | 毎日 | 半可逆・影響大（VM 貸出、1 件 60 分超、費用） | ジョブを追う | ダイアログで **次に回るチケット**を見せてから実行。未着手が無ければ押せない |
| チケットを実行する | 1 件を runner に回す | 毎日 | 同上 | ジョブを追う | ダイアログで PJ・workflow・所要を見せる。dry-run は本番のボタンから離す。今実行できない状態（完了済み）ではボタンを押せなくし、隣に次の一手（未着手に戻す）を置く。案内と空状態の文言も状態に合わせる |
| 状態を手で進める | 手で進めた・戻したを記録する | 週に数回 | 可逆 | 状態の印を光らせ、トーストに「元に戻す」 | 確認なし。元に戻す = `kb set --status <前の状態>` |
| 人間待ちにする | 何を待っているかを残す | 週に数回 | 可逆 | 同上 | メモが必須なので小さなダイアログで聞く |
| 種別・PR・メモを直す | 記録を正す | 月に数回 | 可逆 | 「保存しました」 | 確認なし |
| 状態を実行記録に合わせる | 手で回した run や止まった run の結果をチケットに反映する | 週に数回 | 半可逆・影響大（状態とメモを上書きする） | トーストに「元に戻す」 | 押す前に下見（`kb sync --dry-run`）で対象チケット・run・前後を見せる。run の後にチケットが更新されていれば警告して危険色 |
| VM を返却する | 詰まった VM を戻す | 月に数回 | 不可逆・影響大（動いている run が止まる） | ジョブを追い、sandbox へ | 影響（その VM で動く run、同じ VM を借りている他のチケット）を文で見せる。run があるとき、または共有しているときは **チケット番号の入力**を求める |
| ジョブを止める | 暴走した CLI を止める | まれ | 不可逆・影響大 | 次の一手（状態を合わせる / 返却） | ダイアログ。危険色。既定フォーカスはキャンセル |
| VM の実勢を取る（sandbox ls） | 状態ファイルと実機のずれを見る | 週に数回 | 読むだけ（ssh 数秒） | 同じ画面に結果が出る | ボタンの隣に「取得中」。終わると表が入れ替わる |
| 実行記録・ジョブの詳細を開く | 運転員が結果やログを読む | 毎日・何度も | 読むだけ | — | 表の名前が本物のリンク（Tab で届き、Enter で開く。読み上げでも link）。行の余白のクリックも効く。チケット番号・PR とはリンク先で区別できる。戻ると一覧の位置と絞り込みが残る |
| Claude の鍵を足す・止める | 運転員が、制御系の鍵プール（`keys.json`）を手入れする | 月に数回 | 追加は可逆・削除は不可逆 | 一覧が入れ替わり、トーストに結果 | 「鍵」画面（`g k`。sandbox とログの間）。**値は送るだけで、画面に出るのは末尾 4 文字と名前だけ**（送信後にフォームのトークン欄を空にする）。フラグと「使う」は確認なしで即時（トーストで知らせる）。**使わない設定にする / 消すと、その鍵を使っている貸出に `sandbox reinject` のジョブが起きる**ので、使っているチケットがあるときだけ先に知らせる（削除は危険色 + 名前の入力） |
| ログを見る | 運転員が、起票と配車で何が起きたかを追う | 週に数回 | 読むだけ | チケットを開く | ナビの末尾。主表示は日時・処理・PJ・チケット・結果・理由の表（新しい順）。チケット番号は本物のリンク。チケット番号（前方一致）・PJ・種類（起票 / 配車）の AND で絞り、条件は URL のクエリに持つ。件数は「{n} 件（全 {m} 件）」。導けなかった行は「その他」として原文のまま出す。元のログは下の「元のログを見る」に畳んで残す |
| 設定を見る | 定義を確かめる | まれ | 読むだけ | — | ナビの末尾 |

過去のジョブを開いたときは、ジョブの終了日時とチケットの**今**の状態を並べて出し、その後に人が動かしたチケットには未解決扱いの復旧案内を主表示しない（主ボタンは「チケットを開く」）。

「実行記録に状態を合わせる」は、台帳の run がその run で、かつチケットがまだ実行中のときだけ出す。別の run に進んだ後や、人が状態を動かした後は出さない（後の判断を巻き戻さないため）。

**摩擦の段階**: 可逆 → 確認なし（元に戻す）。半可逆・影響大 → ダイアログ（影響を数字と名前で）。不可逆・影響大 → ダイアログ + 危険色 + 名前入力。同じ危険度の操作は必ず同じ見え方にする。

**ナビの順**は頻度順: ボード / 起票 / 実行記録 / ジョブ / sandbox / 鍵 / ログ / 設定。`g` + 頭文字で移動、`?` で一覧。

## 文言のルール

- **ボタンはユーザーの行為を動詞で**: 「実行する」「起票する」「返却する」「止める」「元に戻す」。「OK」「はい」「実行」は使わない。取り消しは常に「キャンセル」
- **説明・メッセージは「ですます」で一定**。ラベル・見出し・表の列名は名詞。終止形の言い切り（「無い」「要る」）は文言に出さない
- **一文一情報**。先頭に結論。エラーは「何が起きたか」の後に「どうすればよいか」を 1 文
- **主語・目的語を省かない**: 「保存しました」ではなく「チケット 204 を保存しました」
- **開発者の語彙を表に出さない**: セッション / バリデーション / フェッチ / レコード / rc / pid は書かない。CLI 名（`kb run` 等）は見出しの脇に等幅の小文字で添える（主は日本語）
- **責める言葉を使わない**: 「不正」「無効」「失敗しました」より「正しくありません」「できませんでした」
- **行クリックで開く表は、開く先の名前を `<a>` にする**: 行全体のクリックだけに頼らない（キーボードで届かず、読み上げでも押せる場所が分からない）。同じ行に並ぶチケット番号・PR とはリンク先で区別する
- **表記**: 補助動詞はひらがな（ください / いただく / できる）。英数字は半角、括弧は全角「（）」、英数字と日本語の間に半角スペース。感嘆符・絵文字は使わない

### NG / OK

| NG | OK |
|---|---|
| 本当に削除しますか？ → [はい] [いいえ] | チケット 204 の VM を返却しますか？ → [返却する] [キャンセル] |
| task-id が不正 | チケット番号は 3 桁以上の数字で指定してください |
| まだ無い | まだありません。チケットの「実行する」で作られます。 |
| （ボタンが無い画面で）まだありません。上の「実行する」で作られます。 | まだありません。project.yml を置くと実行できるようになります。 |
| （押せる緑のまま）実行する ＋「先に未着手に戻すを押してください」 | 実行するは押せない状態にし、隣に [未着手に戻す（やり直す）] を置く |
| サーバーに届かない | サーバーに届きません。console/bin/console が動いているか確かめてください。 |
| 変える項目が無い | 変える項目がありません。種別・PR・メモのどれかを入れてください |
| セッションがタイムアウトしました | 一定時間操作がなかったため、もう一度合言葉を入れてください |

## 用語集（画面 = CLI = ドキュメント）

| 画面の言葉 | 意味 | CLI / コード |
|---|---|---|
| チケット（番号は「チケット 204」） | 1 件の仕事。`#` は PR 番号にだけ使う（「PR #300」） | `kb` の ticket、sandbox の task-id |
| ボード | 状態ごとのチケット一覧 | `kb list` / `BOARD.md` |
| 状態: 未着手 / 実行中 / レビュー待ち / 完了 / 人間待ち | 工程の位置。人間待ちは横に置く | todo / in_progress / review / done / blocked |
| 起票する | チケットを作る | `kb new` / `glue/bin/intake` |
| 取り込む | 自由文から起票する（LLM 1 回） | `intake` |
| 配車する | 未着手を runner に回す | `glue/bin/dispatch` |
| 実行する | 1 件を runner で回す | `kb run` |
| run / 実行記録 | run は runner が 1 回回ること。実行記録はその記録（画面と `runs/<name>/`） | `runs/` |
| 成果物 | run が残した読み物（報告・計画・検証結果など）。workflow の `outputs` から名前を引く | step の `outputs` |
| 工程 | run の中の 1 ステップ | step |
| ジョブ | このコンソールが起動した CLI 1 本 | `console/jobs/<id>` |
| VM / 貸出 / 返却する | sandbox の仮想マシンと、その貸し出し・返却。貸出先が無い VM は「空き」 | `sandbox take` / `release` |
| 稼働状態: 起動中 / 停止中 / 節電で停止中 | VM の電源が入っているか。貸出とは別の軸。返却しても VM はすぐには止まらないが、使われないまま既定 24 時間経つと「停止候補」になり、候補が既定 10 台を超えると古いものから節電で止まり（`sandbox idle-stop`）、次の貸出が自動で起動する。候補のまま起動している VM には「停止候補」の印が付く | `sandbox ls` の STATUS、Proxmox の running / stopped、`idle-stop.json` |
| 共有 | 同じ VM が複数のチケットに貸出中の状態。件数（貸出）と台数（VM）を分けて出し、返却の前に影響するチケットを見せる | 台帳（`state.json`）に同じ vmid の項目が 2 つ以上 |
| PJ | 貸出先のリポジトリ（プロジェクト）。画面では常に PJ | pj |
| dry-run | 状態を変えずに手順だけ組む | `--dry-run` |
| 日時・所要 | 記録の時刻はオフセット付き（ADR-0026）。画面はブラウザーの時間帯で出し、記録の時間帯が違えば左下に添える。所要は記録と「今」の差だけで出し、時刻が無ければ「時刻の記録なし」 | `started` / `finished` / `elapsed_s` |

「タスク」「プロジェクト」「レコード」は画面に出さない（検査で弾く）。

## レビューの 2 つの問い

1. このボタンのラベルだけを見て、押すと何が起きるか説明できるか
2. このエラーを読んで、次に何をすればよいか分かるか

文言を足したら `python3 -m unittest console.tests.test_strings -v`。実際の幅と実データ（長い題名・0 件・100 件）で 1 度は見る。
