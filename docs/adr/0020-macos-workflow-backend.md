# ADR-0020: 共通workflowからmacOS pull workerを実行する

日付: 2026-09-07 / 状態: 採用

## 背景

macOSアプリのREADME整備を実際のMac VMで起票からPR作成まで通すdogfoodingが依頼され、未実装だった連携部分の開発も対象に含めることが承認された。ADR-0018のprobe/guest-exec基盤を、既存のkanban・MCP・workflowへ接続する。

## 決定

- プロジェクトに `backend: macos-pull` と `worker` を指定する。未指定の既存プロジェクトは従来のProxmox経路を使う。
- workflowの状態遷移、役割、入力・出力、記録は共通runnerに残す。Mac固有の準備、コマンド転送、文書ゲート、PR作成、成果物回収は `workflow/lib/macos.py` が担う。
- 制御系のSQLiteにrun単位のleaseを置く。1つの操作が完了してもleaseを保持し、別runの割り込みを防ぐ。Mac側もleaseを永続化し、同じ所有者の操作だけを受け付ける。
- 基準イメージと専用ゲスト名はMacのローカル設定に固定する。prepareは未使用の名前にcloneし、releaseは所有するゲストの停止と削除を確認する。既存VMを勝手に引き取らない。
- ネットワークは引き続きMac発のHTTPSだけ。制御系からMacへのSSH経路を追加しない。ホストのホーム、クリップボード、音声を共有せず、SoftnetでプライベートIPv4・tailnet宛てを遮断する。
- 認証情報を含むstdinは0600の一時ファイルで保持し、認証済みworkerへHTTPSで渡す。操作DB、操作表示、コマンド文字列には値を含めない。結果受領後に一時ファイルを削除する。
- 成果物は作業ディレクトリ直下の通常ファイルをサイズ制限付きで回収する。認証情報は除外し、制御系で名前・SHA-256・サイズを照合する。回収に失敗したらゲストを削除しない。
- `docs` workflowを追加し、計画、執筆、文書ゲート、レビュー、PR作成を行う。dry-runは全stepの構成確認が成功すれば終了コード0にする。

## 制約と運用

初期のMacバックエンドが扱うcode stepは `gates.sh` と `pr-create.sh`。`merge-pr`、複数OSをまたぐrun、GUI配信、リソース自動調整は含めない。基準VMのアカウント・ネットワークサービス・ツール群は管理者が準備する。実機固有の設定と進捗は非追跡のworkspaceに記録する。

切断や結果不明を理由に、別VMへ同じ処理を自動再割当しない。`--resume` には既存leaseが必要で、返却できない場合は所有者を記録したまま復旧する。`--keep` は成果物回収後もleaseを保持する。

日付をまたいだ `kb run --resume` はチケットに記録されたrun名を使い、runnerでもプロジェクトとチケットの一致を検証する。準備途中からの再開は、同じleaseの稼働中ゲストで、認証情報・リポジトリ・工程履歴がまだない場合に限る。途中まで作成されたリポジトリや停止したゲストは自動で作り直さない。

SoftnetがPATH上にあり、root所有・SUID設定済みであることをworkerが通知する。基準イメージまたはこの設定が未完了なら、直接実行はVMを割り当てる前に待機し、自動dispatchは対象を見送る。GitHub App tokenの発行にはrunnerと同じリポジトリ内のsandbox CLIを使い、PATH上の古いインストールを誤って呼ばない。
