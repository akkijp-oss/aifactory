# 0007 複数 PJ を同居させるため、テンプレートは 911x を PJ ごとに割り、VM の IP は VMID から導く

日付: 2026-09-06 / 状態: 採用（README の「命名・採番・アドレス」を一部変更）

## 状況
最初から PJ を 2 つ同時に持つとメンテナが決めた（2026-09-06）。当初の採番は PJ テンプレート = 9110 / 10.77.0.110、プール IP = `10.77.1.{PJ 内連番}` で、PJ が1つの前提だった。2 PJ 目を作ると
- テンプレート作業用 IP 10.77.0.110 が両 PJ で衝突し、並行して焼けない
- プールの `sb-<pj-a>-01` と `sb-<pj-b>-01` が両方 10.77.1.1 になり衝突する

## 決定
| 対象 | 旧 | 新 |
|---|---|---|
| PJ テンプレート VMID | 9110 固定 | **911x を PJ ごとに割る**（例: `<pj-a>` 9110、`<pj-b>` 9111。`TPL_VMID` で渡す） |
| PJ テンプレート作業 IP | 10.77.0.110 固定 | **10.77.0.(VMID−9000)**（9110 → .110、9111 → .111） |
| プール VM の IP | 10.77.1.{PJ 内連番} | **10.77.1.(VMID−9200)**（9201 → .1、9204 → .4）。PJ 横断で一意 |
| プール VM の名前 | `sb-{pj}-{NN}` | 変更なし（NN は PJ 内連番。IP とは無関係になる） |
| VMID の割当 | 9200+連番 | 9201 から空きを探す（PJ 横断） |

`sandbox ls` は IP を VMID から計算して表示する。DNS の常設名 `sb-{pj}-{NN}.sb.internal` はプール作成時に実 IP で登録する。

## 理由
- VMID は Proxmox が一意性を保証する。そこから IP を導けば台帳を持たずに衝突しない
- 名前の連番は人が読むためのもの。IP と切り離しても困らない（到達は DNS 名か `sandbox ls` の表示で行う）

## 結果（トレードオフ）
- プールは 9201〜9299 の 99 台が上限（10.77.1.1〜99）。足りなくなったら 10.77.2.x に広げる新 ADR
- 既存の汎用プール `sb-generic-01..03`（9201〜9203 = 10.77.1.1〜3）は新規則でも同じ IP なので作り直し不要
- どの VMID がどの PJ かは名前で判別する（`qm list`）
