# ADR 0082: MCP は配ったスキーマを入口で強制する。未知のキーと必須の抜けはツールエラーにし、値の型と意味の判定は core に残す

- 状態: Accepted
- 日付: 2026-09-16

## 状況

`console/bin/mcp` は全ツールの入力スキーマを `schema()` で組み、`tools/list` で
`"additionalProperties": false` と `"required": [...]` を付けて配っていた。しかし `tools/call` は
`params["arguments"]` を**一切検査せず**そのまま `t_*` ハンドラ → `core.*` に渡していた
（`bin/mcp` に jsonschema の import も手書きの検証も無かった）。

`core` 側は「キーが無い＝触らない」を規則にしている（`ticket_action` の `set` は `if "depends_on" in b …`）。
このため**スキーマに無いキーは誰にも見られずに消える**。チケット 585 の実測（管理役が配備済みの制御系で再現）:

```
ticket_action(id=588, action="set", note="（正当なメモ）",
              nonexistent_key_probe_585="…")
→ rc=0 / isError: false。note は反映され、nonexistent_key_probe_585 は警告も無く捨てられた
```

つまり **宣言と挙動が食い違い、弾くかどうかがクライアント任せ**になっていた（Claude Code のクライアントは弾かない）。
起票の動機だった `depends_on` は #586 で口が足されて解消したが、**キー名を打ち間違えた時に同じ事故が起きる**
性質はそのまま残っていた（`depend_on` / `state` と書けば「成功した」と返り、値だけ消える）。呼び手は MCP 越しの
AI やスクリプトなので、返り値が成功に見える限り気づけない。

## 決定

1. **`tools/call` の入口で引数を検査する**（`check_args()`。`fn(args)` の手前で呼ぶ）。
   - **スキーマに無いキー**があればツールエラー（`core.ApiError` → `isError: true`）。文言に、来た未知のキーと
     受け付けるキーの一覧を載せる。
   - **`required` のキーが無い**ときも同じくツールエラー。
   - `arguments` が object でないときも同じ。
2. **許可リストは `TOOLS` の各 `schema()` がそのまま正本**。新しい表を作らない。宣言（`tools/list` が配る内容）と
   検査（`tools/call` が効かせる内容）が同じ 1 つの定義から出る。
3. **見るのはキー名だけ**。値の型（`id: "560"` のような文字列の整数）と意味の判定は、今までどおり
   `arg_int` と `core` の仕事にする（ADR-0015: 判定の正本は core）。入口の仕事は「宣言した口以外を通さない」ことに限る。
4. **`null` は「キーが在る」として通す**。`{"note": null}` は `core` が `is not None` で見分けており、
   これは現行の契約である。未知キーの判定はキー名だけで行う。

## 理由

- **黙って捨てるのが最も悪い**。`isError: false` で `kb` の出力 1 行が返るので、呼び手は「書けた」と読む。
  無視した項目を戻り値に**載せる**案（警告方式）も検討したが、`isError: false` のままでは同じ誤読が残る。
- **宣言を本物にするだけ**で、それに従うクライアント（`additionalProperties: false` を守る実装）は何も変わらない。
- リポジトリ内で MCP を叩く経路は `console/tests/` だけで、スキーマ外のキーは送っていないことを確認した。
  Web コンソールは HTTP（`bin/console`）で、MCP を通らない。

## 影響

- **余計なキーを送っていた呼び手は落ちるようになる**（`isError: true`）。これが狙いだが、リポジトリの外に在る
  呼び手（`aifactory-drive` スキルなど）は VM から実測できない。配備後に、弾かれた呼び出しが出ていないかを見ること。
  落ちるのは「今まで黙って無視されていた呼び出し」だけで、無視された項目は元々効いていない。
- 必須の抜けも同じくツールエラーになる。今までは各ハンドラの `arg_int` などが個別に落としていた（文言は変わる）。
- 型の緩さは**変えない**。`id: "560"` は今までどおり通る。

## 代替案

- **戻り値に「無視した項目」を載せるだけ（警告方式）**: `isError: false` のままなら、票の動機
  （「成功と返るのに書かれていない」）が残る。採らない。
- **jsonschema で完全検証する**: 依存を増やし、型まで厳しくなって現行の呼び手が落ちる。入口の仕事を
  キー名だけに絞る方が、壊す範囲が読める。
- **`additionalProperties: false` の宣言をやめる**: 食い違いは消えるが、打ち間違いは黙って捨てられたまま。採らない。
