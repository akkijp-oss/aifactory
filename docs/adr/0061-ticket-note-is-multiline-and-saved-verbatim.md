# ADR 0061: チケットの `note` は複数行を正本とし、画面の編集欄は textarea・保存は無変換にする

- 状態: Accepted
- 日付: 2026-09-10

## 状況

チケットの `note` は 1 行の見出しではなく、複数行の申し送りとして使われている。
`kb run` が先頭に `[run] ...` の 1 行を足し、残りの行は人のもの、という約束が既にある（ADR-0048）。
MCP の `ticket_new` / `ticket_action` も改行込みの `note` をそのまま渡す。記録の側は最初から複数行を保てている。

- `console/lib/core.py` の `ticket_action` は `note` を素通しで `kb set --note` に渡す（キーが無い＝触らない / 空文字列＝消す）。
- `kanban/bin/kb` の `update()` も値を素通しで sqlite に入れる。改行を空白に潰すのは `render()` だけで、
  これは `board.md` の表を 1 行に収めるための**表示側**の処理。正本の DB は無傷。

一方、チケット詳細（`console/static/app.js` の `viewTicket()`）の「項目を直す」のメモは `<input type="text">` だった。
HTML の value sanitization algorithm は `input` の値から CR/LF を捨てるので、

1. 複数行の `note` を開くと編集欄では行が連結されて 1 行になり、読めない。
2. **何も編集せずに「保存する」を押しただけ**で、その連結された 1 行が `kb set --note` に渡り、記録側の改行が失われる。
   （2026-09-10 の実操作検証で確認。`history` の `note.old` には実改行があり、新しい値には無かった。）
3. `tDraftSave()` の差分判定（`el.value !== tkServer.note`）も常に真になり、無編集なのに下書きが残る偽陽性が出ていた。

読み取り専用のメモ枠（`.panel.note`）にも `white-space` の指定が無く、複数行のメモが 1 行に見えていた。

## 決定

1. **`note` の正本は複数行**。改行は記録の一部として扱い、画面はそれを落とさない。1 行に潰すのは
   `kb render` の `board.md` の表とボードのカード（1 行が約束）だけに閉じる。表示の都合を記録に持ち込まない。
2. **編集欄は `<textarea>`**。開始タグ直後の改行 1 個は HTML パーサーが捨てるので、`>` の直後に改行を 1 個入れて相殺する
   （改行で始まるメモが 1 文字削れないようにする）。高さは `.h80` に抑え、伸ばすかどうかは `resize: vertical` で利用者に委ねる。
3. **保存は無変換**。`actions['set']` は `$('set-note').value` をそのまま送る（`.trim()` を掛けない）。
   無編集で保存したときに 1 バイトも変わらないことを、この一点で保証する。
   ただし**空白だけの入力は空文字列に落とす**（`note.trim() ? note : ''`）。「メモを空にする」操作は ADR で決めた
   「空文字列＝消す」の約束のまま残す。
4. **読み枠は `white-space: pre-wrap`**。編集欄だけ直しても「読みにくい」が残るので、同じ画面の中で揃える。
5. **記録の側（`core.py` / `kb` / `mcp`）は変えない**。改行を保つ実装になっていて、直す理由が無い。

## 結果

- 複数行のメモが読める形で編集でき、種別や PR だけを直して保存してもメモが壊れない。
- `tDraftSave()` の偽陽性が消える（textarea の `value` はサーバー値と素直に比較できる）。
- JS を動かす基盤が CI に無いので、この約束は `console/tests/test_console.py` の 2 本で守る。
  ソース検査（`textarea` であること・`trim` していないこと・`.panel.note` が `pre-wrap` であること）と、
  改行入り `note` の API 往復（他項目だけの保存で触らないことを含む）。
- 操作パネルの縦がわずかに伸びる。80px に抑えて許容した。

## 代替案

- **`input` のまま、保存前に元の値と比べて未編集なら `note` を送らない。** 「無編集保存で壊れる」は消えるが、
  改行を 1 行に潰して見せる問題も、複数行を書き足せない問題も残る。症状の 1 つだけを塞ぐことになる。
- **記録の側で改行を正規化する（1 行に潰す）。** ADR-0048 の「残りの行は人のもの」と `ticket_new` の実際の使われ方に反する。
- **`contenteditable` の欄にする。** 貼り付けで書式が混ざり、`value` で素直に読めない。得るものが無い。
