# 0003 プールは使い回し + スナップショット巻き戻し

日付: 2026-09-05 / 状態: 採用

## 状況
sandbox の粒度。1タスクごとに VM を作って壊す（使い捨て）か、VM を長生きさせて使い回すか。メンテナは「シンプルに使い回したい」。

## 決定
PJ テンプレートから linked clone した VM を **N 台常駐**させ、貸出前の状態を **RAM 込みのスナップショット `clean`** で保存する。タスク終了（`release`）と途中リセット（`reset`）は `clean` への巻き戻しで行う。

## 理由
- 素の使い回しは DB の残骸や中途半端なブランチが次のタスクに漏れ、隔離の意味が薄れる
- 使い捨ては毎回 cloud-init と依存インストールが走り遅い
- 巻き戻しなら、キャッシュ（依存・DB seed・起動済みアプリ）は残しつつ状態は毎回きれいになる
- RAM 込みにすると巻き戻し直後からアプリが応答する。品質優先

## 結果
- テンプレート更新時はプールを作り直す（`OPERATIONS.md`）
- `/run/sandbox`（tmpfs）に置いたトークンは巻き戻しで消える（0005 の前提）
- 並列数 = プール台数。足りなければ `40-pool.sh` で足す
- linked clone はテンプレートと同じノードにしか作れない。複数ノード化はテンプレートの複製が要る（未決）
