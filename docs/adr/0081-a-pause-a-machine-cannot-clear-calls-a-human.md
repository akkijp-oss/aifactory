# ADR 0081: 機械が片付けられない一時停止（鍵待ち / 回数超過）は `blocked_by_key` と呼んで人を呼ぶ。配車は一時停止の一覧を読めなければ止まる

- 状態: Accepted
- 日付: 2026-09-16
- 関連: ADR-0079（下見と配車が同じ票を選ぶ。決定 5 で「後ろ 2 つが残った板をどう知らせるかは別票」と先送りした分を本 ADR が引き受ける）、
  ADR-0043（一時停止と再開）、ADR-0046（鍵が無いときの一時停止）、ADR-0074 決定 2・決定 5（状態と理由の語彙）、
  ADR-0015 / ADR-0078（判定の正本は core の 1 か所。呼び手に規則を写さない）

## 状況

ADR-0079 で PM と下見の語彙に入れた `blocked_by_pause`（解除前の一時停止しか残っていない）の中には、
**解け方の違う 3 つ**が混ざっている。

| 一時停止の種類 | `resume_plan` の返り | 誰が解くか |
|---|---|---|
| 利用枠切れ（`paused: quota`） | `until` に解除時刻。時刻を過ぎれば `ready` | **機械**。`aifactory-resume.timer` が 5 分ごとに `dispatch --resume-paused` を呼ぶ |
| 鍵待ち（`paused: nokey`） | `until` は `null`。`ready` は鍵プールの中身（`key_pool_has`）で決まる | **人**。`sandbox token set` で鍵を登録するまで、時間では変わらない |
| 回数超過（`hits_exceeded`） | `ready` でも自動では回さない | **人**。利用枠を確かめるまで |

timer の待ち行列は `ready` の票しか拾わない（`glue/bin/dispatch`）。
つまり後ろの 2 つは**機械が一生片付けない**のに、PM は `state: idle`（回すチケットを待っています）/
`action: none` のままで、画面にも「どの票が・何を待っているか」が出ていなかった。
★**板に鍵待ちしか残っていないと、画面も判断ログも「人がやることは無い」と言い続ける。**

同じ板で、配車側にも別の取り違えがあった。`glue/bin/dispatch` の `resumable()` は
`kb resumable --json` の標準出力を自分で読み、**読めなければ `{}`（= 一時停止 0 件）に倒していた**
（`sh()` は `check=True` を渡しておらず rc を見ない。rc≠0 で標準出力が空なら `[]`、壊れた JSON なら例外を握って `{}`）。
一方 core の `pm_resume_plans` は読めなければ `ApiError` を上へ出す。
★**同じ「読めなかった」に対して、下見は止まり、配車は「0 件」として回し続ける**——判断が 2 つに分かれていた。

## 決定

1. **人が動くまで解けない一時停止を別の語で呼ぶ**: `blocked_by_key`。
   `blocked_by_pause` は「解除時刻を待つだけ（機械が片付ける）」に狭める。
   判定は `core.pm_pause_needs_human(plan)` の 1 か所（`paused == "nokey"` または `hits_exceeded`）で、
   時刻や回数の規則はこれまでどおり `kb` の `resume_plan` が正本（core にも dispatch にも写さない）。
2. **語を足すときは `PM_NEXT_REASONS` と `PM_REASON_CODES` の両方**に入れる（#570 で片方だけ更新した事故の再発防止）。
   文言（`console/static/strings.js` の `pm.next` / `pm.reason`）まで含めて 1 組で、
   既存のテストが「語彙に文言の無いものがある」で落ちる形を維持する。
3. **PM は `idle` ではなく `blocked`（人の確認待ち）にする**。
   状態の語は ADR-0074 決定 2 の 4 つのままで、5 語目を作らない。
   格上げするのは「人が動くまで解けない一時停止しか残っていない」ときだけで、
   止まった run の人間待ち（`needs_human`）とは `next.reason` / `proposal.reason_code` で区別する。
   ★**ADR-0079 決定 5 の「この状態は `blocked` に格上げしない」は、鍵待ち・回数超過については本 ADR が置き換える**
   （利用枠切れだけの板は今までどおり `idle`。既存 ADR の本文は書き換えない）。
4. **画面は「どの票が・何を待っているか」を出す**。PM 画面（`#/pm`）の「次に回すもの」に、
   飛ばした一時停止の票を 1 票 1 行で並べる（材料は同じ tick が積んだ `skipped_by_pause`。画面で判定を作らない）。
5. **`dispatch` は一時停止の一覧を `core.pm_resume_plans` から読む**（ADR-0078 と同型。kb の呼び方と rc の見方は core の 1 か所）。
   読めなければ**何も回さず終了コード 1** で終える。「読めなかった」を「0 件」に倒さない。
   ★`OSError`（kb が無い・実行できない）は**握らない**。握ると「バイナリが無い」まで「0 件」になり、直そうとしている取り違えが広がる。
6. `kanban/bin/kb` は変えない（`resume_plan` の返りに区別する材料はすでに全部ある）。

## 理由

- ADR-0074 決定 2 の `idle` は「回すチケットを待っている」＝**待てば進む**という意味で、
  人が動くまで進まない板をそこに置くと、状態の語そのものが嘘になる。ADR-0079 が「放っておけば機械が片付けると読んではならない」
  と書いた注意を、**機械が読める形**（語彙と状態）にしたのが本 ADR。
- 語を足す代わりに「facts を画面に出すだけ」でも「どの票が何を待っているか」は見える。
  それでも語を足したのは、**PM 自身の判断（`state` / `reason_code` / 判断ログ）が変わらないと、
  画面を見ていない人には届かない**から（判断ログは後から数える記録でもある）。
- `dispatch` の「読めなかった」を `rc 1` で落とすのは、5 分ごとの timer の journal が赤くなることを承知の上で選ぶ。
  `kb resumable` が読めない間は、止めてある票を初めから回す事故が起きうるので、**気づかせる側に倒す**
  （`pm-tick` の「今日は何もしない」を rc 0 で返す運用（ADR-0074 決定 1）は正常系の話で、ここは正常系ではない）。

## 結果（トレードオフ）

- `blocked_by_pause` の意味が狭まる。この語を読む側（画面・判断ログの集計）は、
  鍵待ち・回数超過が `blocked_by_key` に移ったことを前提に読む必要がある。**判断ログの過去の行はそのまま**で、
  当時の語（`blocked_by_pause`）のまま残る（記録を書き換えない）。
- 鍵待ちの板では PM が `blocked` になるので、**「人の確認待ち」の見え方が増える**。
  これは意図した増加で、減らしたければ鍵を登録するか、その票を `blocked` にして板から外す。
- `dispatch --resume-paused` が rc 1 で終わる経路ができる。timer の journal に赤が並ぶのは
  「`kb resumable` が壊れている」ことの通知として使う。rc 0 に戻したくなったら、
  **「何も回さない」と文言は変えずに** 終了コードだけを変えること（テストが rc を固定している）。
- 回数超過（`hits_exceeded`）を鍵待ちと同じ語に入れた。どちらも「人が確かめるまで解けない」で、
  人にしてほしいことは違う（鍵を登録する / 利用枠を確かめる）。その違いは画面の 1 行（`pm.pause.*`）で言い分け、
  **語彙は増やさない**（語を増やすほど、足し忘れる箇所が増える）。
