# ADR 0083: 私有 PJ 名は 1 つ残らず検査語に載せ、書き換えられない既存 ADR だけをファイル名で名指しして例外にする

- 状態: Accepted
- 日付: 2026-09-16

## 状況

`bin/oss-check.sh` は「公開前チェック。git 追跡ファイルに、環境固有の名前・私有 PJ・秘密情報らしきものが
残っていないかを機械的に見る」ゲートで、私有 PJ 名を `PAT`（1 本の正規表現）で弾いている。
この一覧は手で並べたもので、後から増えた PJ が追記されていなかった。**この工場の私有 PJ 2 件が抜けていた。**

抜けの実害はチケット 584 の run で実際に出た。実装役が新しいテストのコメントに私有 PJ 名を 1 つ書き、
`bin/oss-check.sh` は緑のまま gates 9/9 PASS で review へ進み、**reviewer の目視だけが防波堤になった**。
機械が拾えない以上、同じことは何度でも起きる。

抜けていた 2 語のうち片方は追跡ファイルに 1 件も無く、そのまま足せる。もう片方は**既存の追跡ファイル 13 件**に
既出で、単純に足すと `bin/oss-check.sh` が既存ファイルで赤になり、**全 run の gates が落ちる**。
内訳は既存 ADR 7 枚と、それ以外 6 件（未リリースの `changelog.d/` 1・`workflow/lib/` 1・テスト 2・website ja/en 2）。
この PJ の規則は「既存の `docs/adr/*.md` を書き換えない（新しい番号で追加する）」なので、**ADR 側は直せない**。

`ALLOW`（既存）は「行の内容」を許す仕組みで、ネットワーク表記の許可にしか使っていない。パスの除外には使えない。

## 決定

1. **実在する私有 PJ 名は 1 つ残らず `PAT` に載せる。** 一覧の出所は制御系の `project_show` /
   `sandbox_status` が返す PJ 一覧で、公開してよい PJ（サンプルとこのリポジトリ自身）以外は全部載せる。
   **推測で語を足さない**（実在しない語は誤検知になり、開発が止まる）。
2. **既存 ADR は書き換えず、`ALLOW_FILES` に「ファイル名を 1 枚ずつ名指し」して `== 3` 節の検査から外す。**
   除外は `git ls-files` の段（検査するファイルの集合）で効かせる。`ALLOW` には足さない
   ——`ALLOW` に語を足すと**どのファイルでもその語が素通り**になり、検査の目的そのものが消えるからである。
3. **`docs/adr/` をディレクトリ単位では除外しない。** 名指しなので、**新しく足す ADR は今までどおり検査される**。
4. **ADR 以外の既出は、私有 PJ 名を使わない形に直す**（票番号の参照・コマンド例の引数であって、PJ 名でなければ
   成立しない記述ではない）。利用者向けの website の例は特に直す価値がある。
5. **`--staged`（pre-commit）経路には例外を置かない。** 同じ `PAT` を共有するので新しい語はそのまま効き、
   既存 ADR は書き換えない限り差分に出ない。出たなら弾いてよい。
6. **退行注入テストを `workflow/tests/test_oss_check.py` に置く。** 一時 dir に偽の checkout を作って
   スクリプトを実際に回す（`test_changelog_release.py` と同じ流儀）。検査語そのものはテスト本文に書かず
   連結で組み立てる（`test_scrub_secrets.py` と同じ理由）。

## 理由

- **穴を残したまま「正直に諦める」案（語を足さない）は採らない。** 新規の混入を人の目視に頼る状態が続き、
  584 と同じ事故がそのまま再現する。
- **例外はファイル名の名指しに限る**ことで、例外が黙って広がらない。ディレクトリ除外にすると、
  新しい ADR への混入が永久に見えなくなる。今回の混入元になった run も、新しい文書を足す側だった。
- **過去の決定記録は事実として残す**のがこの PJ の作法で、そこだけは機械の検査より優先する。
  代わりに「そこには新しい行を足せない（足すと赤くなる）」という制約は付かない
  ——例外は行ではなくファイルなので、既存 ADR の中では検査が効かないことは承知の上である。

## 影響

- 私有 PJ 名を新しく書いた追跡ファイルは、全量経路（run の gates）でも `--staged`（pre-commit）でも弾かれる。
- 例外に載せた既存 ADR だけは検査されない。**例外のファイルが消えたら例外も落とす**ことをテストで縛る
  （`ALLOW_FILES` の各パスが実在すること）。
- 新しい私有 PJ が増えたら `PAT` に足す作業が要る。自動で取る案（制御系に問い合わせる）は採らない
  ——`bin/oss-check.sh` は CI でもネットワーク無しで走る必要があり、検査語が実行環境で変わるのは避ける。

## 代替案

- **`ALLOW` に語を足す**: 全ファイルで素通りになり、検査の意味が消える。採らない。
- **`docs/adr/` を丸ごと除外する**: 新しい ADR への混入を拾えない。採らない（決定 3）。
- **既存 ADR を書き換えて語を消す**: この PJ の禁止事項。採らない。
- **語を足さず現状維持**: 票が挙げた案だが、584 の事故が再発する。採らない。
