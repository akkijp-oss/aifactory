# ADR 0026: 記録する時刻はオフセット付き ISO 8601 にする

- 状態: Accepted
- 日付: 2026-09-07

## 状況

記録の書き手が 2 流儀あった。`workflow/bin/run`（`started` / `finished` / `current.since` / `history[].at`）・`kanban/bin/kb`（`created` / `updated` / 履歴の `at`）・`console/lib/core.py`（ジョブの `started` / `finished`、`overview` の `now`）はオフセットの無い `2026-09-08T00:21:00`、`sandbox` CLI の `since` だけが `date -Iseconds` のオフセット付きだった。

ブラウザーは JavaScript の `Date` にそのまま渡すので、オフセットの無い時刻を**ブラウザーの**時間帯として読む。サーバーとブラウザーの時間帯が違うと、実行中の run の「開始から」がその時差ぶんずれる。終了後は runner が書いた `elapsed_s`（秒）を表示するため、正しい値に飛ぶ。同じ実行が実行中は「9 時間 9 分」、終了後は「10 分」に見えていた（チケット 235）。sandbox の貸出だけ正しく見えたのは、オフセットが付いていたからである。

## 決定

1. 記録する時刻はオフセット付き ISO 8601（`2026-09-08T00:21:00+00:00`）にする。書き手は `datetime.datetime.now().astimezone().isoformat(timespec="seconds")` を使う
2. オフセットの無い古い記録は、**書いたホストのローカル時刻**とみなす。console が読むときに `ts_aware()` でそのホスト（＝制御系）の時間帯を補う。記録そのものは書き換えない
3. API（HTTP / MCP）が返す時刻はすべてオフセット付きにする。日時として読めない値（v0 の `- 日時` の自由文など）はそのまま返す
4. 画面はブラウザーの時間帯で表示し、その時間帯を明示する。記録の時間帯とブラウザーの時間帯が違うときは、その旨を添える
5. 経過時間は「オフセット付きの時刻」と「今」の差だけで計算する。ブラウザーの時間帯によって値が変わってはならない

## 理由

時刻の基準を記録そのものに持たせれば、読む側（ブラウザー・MCP のクライアント・別ホストのワーカー）が時間帯を推し量る必要がなくなる。表示側だけを直す案（console が「サーバーの時間帯」を別に配って補正する）もあるが、記録が曖昧なままなので、制御系以外が記録を書くようになったときに同じ不具合が戻る。

## 結果（トレードオフ）

- 制御系**以外**のホストで書かれた古い naive な記録は、そのホストと制御系の時差ぶんずれたまま読まれる。過去の記録から真の時間帯は復元できないので、これは受け入れる
- 記録の文字列が長くなる。`runs/` の並び替えは `started` の文字列の辞書順に依っているが、書式は秒まで同じで先頭が年から始まるため、新旧が混ざっても順序は崩れない
- `kb` / runner の出力形式が変わるので、`state.json` や `kanban.db` を自前で読む道具があれば追随が要る。読む側は `datetime.fromisoformat` で新旧どちらも読める

## 制約

- 比較（`console/lib/core.py` の `after()`）は入口で時間帯を補ってから行う。オフセットの有無が混ざった比較は例外になり、黙って False になっていた
- `glue/bin/intake` と `glue/bin/dispatch` がログとチケット末尾に書く時刻は naive のままとした。画面には出ないため今回の範囲外とする
