# ADR 0046: 要る用途の Claude の鍵が鍵プールに無ければ、env の鍵に落ちず一時停止し、鍵が登録されたら機械が回し直す

- 状態: Accepted（ADR-0045 の「env の鍵は保険」を取り下げる。ADR-0043 の一時停止の仕組みを鍵なしにも使う）
- 日付: 2026-09-10
- メンテナの判断: 「鍵がない場合は、一時停止するのが正しい」

## 状況

ADR-0045 で鍵プールを正本にしたが、プールに用途の合う鍵が無いときは PJ / 全体の env の鍵（非推奨）に落ちる規則を残していた。
これだと、プールで鍵を全部止めたつもりでも env の鍵で run が走り、「どの鍵が使われるか」が画面から読めない。
鍵を止める・入れ替えるのはプールの操作だけで済むべきで、鍵が無いときの正しい振る舞いは「動かないこと」である。

## 決定

1. **プールに 1 本でも鍵があれば、env の Claude の鍵は VM に渡さない。** `take` / `reset` / `reinject` はプールで選んだ鍵だけを書き、
   選ばなかった用途の変数は空にする。プールが空（ファイルが無い・0 本）のときだけ従来どおり env の鍵（非推奨）を使う。
2. **要る用途の鍵が無ければ `take` は VM を取らずに「鍵なし:」で止まる。** 要る用途は runner が workflow の agent step のモデルから
   決めて `sandbox take --need=fable,other` で渡す（既定は両方）。`reset` / `reinject` は貸出台帳に残っている用途を要る用途とする。
   止まった回は鍵の使用回数を動かさない。プールも env も空なら同じく「鍵なし:」（今までの `[warn]` で通す振る舞いはやめる）。
3. **runner は「鍵なし:」を `failure: "nokey"` で記録し、`needed_keys` を残す。** VM を取っていないので工程は 1 つも走らない。
4. **kb はチケットを todo に戻す。** `kb resumable` は鍵プール（`keys.json`。用途と有効だけ読む）に `needed_keys` の鍵がそろったら
   `ready` にし、`dispatch --resume-paused`（5 分ごとの timer。ADR-0043）が**初めから**回し直す（続きではないので `--from` は付けない）。
5. **console** は run の結果に「Claude の鍵が無いので一時停止しました（必要: …）。「鍵」画面で登録すると自動で回し直します」と出す。

## 対象外

- 工程の途中で鍵が拒否された（`failure: "key"`。無効・失効・残高不足）は今までどおり人間待ち。鍵の中身が壊れている場合で、
  登録の有無では判断できないため。
- `intake`（`ctl.env` の鍵）と pull backend の worker は ADR-0044 / 0045 のまま対象外。

## 結果

- 鍵の「使う / 使わない」はプールの操作だけで決まり、env に残った古い鍵が勝手に使われることが無い。
- 鍵を全部止めれば工場は止まり、登録すれば timer が拾って再開する。人が `kb run` を打ち直す必要は無い。
- 実機（main テナント）では global の env に残していた保険の鍵も消す（プールが正本）。
