# 0002 sandbox は Proxmox VM、アプリは VM 内ネイティブ

日付: 2026-09-05 / 状態: 採用

## 状況
sandbox の実体として、git worktree / Docker コンテナ / クラウド microVM（E2B 等）/ 自前の Proxmox の VM か LXC、の選択肢があった。メンテナは自前の Proxmox クラスタを持っている。

## 決定
Proxmox の **VM**（LXC ではない）を1エージェント1台で使う。VM 内では Rails 等を **ネイティブ**に動かし、Docker は使わない。

## 理由
- worktree は DB・ポート・プロセスが共有され、隔離にならない。動画も「始めるには良いが終着点ではない」
- クラウド microVM は月額と外部依存が増える。品質優先だが、自前に十分な資源（メモリ 200GB 級のホスト複数）がある
- LXC は軽いが、中で Docker を動かすと権限まわりが面倒。VM は素直
- ネイティブ実行にすると DB が VM ローカルになり、スナップショット巻き戻しで DB も一緒に初期化される（0003 と噛み合う）
- 各 VM が固有 IP を持つので、ポート衝突が原理的に起きない

## 結果
- Ruby / Node の版が PJ で違うので、テンプレートは base + PJ 層の2層になる
- 1台 4GB 程度の RAM を食う。ホストは Proxmox ホスト 1 台（本文では `pve1`）で v0 は 2〜3台
- VM の起動は cloud-init 経由。LXC より数十秒遅いが、プールで常駐させるので貸出時には効かない
