# ADR 0079: 配車の下見は「実際に回る票」を見せる。選び直しは core の 1 か所（`pm_pick_next`）を通す

- 状態: Accepted
- 日付: 2026-09-15
- 関連: ADR-0043（一時停止と再開。「下見の表示は別票」と書いて先送りした分を本 ADR が引き受ける）、
  ADR-0046（鍵が無いときの一時停止）、ADR-0074 決定 1・決定 5（判定の正本は core / 理由の語彙）、
  ADR-0077・ADR-0078（先行条件。`kb next` は薄いまま）

## 状況

コンソールのボードで「配車する」を押す前の**下見**（`GET /api/next` → `core.ticket_next()`）は、
`kb next --json` の返りを**そのまま**画面に出していた。`kb next` は todo を id 順に 1 件返すだけの口で、
先行条件も一時停止も見ない（ADR-0074 決定 1 / ADR-0077 / ADR-0078 が「薄いまま」と決めている）。

一方 `dispatch` は、板と run の記録だけで確かめられる条件で票を飛ばす。**下見はそれを 1 つも見ていなかった**。

| 下見が見せる票を dispatch が飛ばす理由 | いつ入ったか | 出典 |
|---|---|---|
| 未完了の先行票を持つ | #573 | ADR-0078 決定 1 |
| 解除前の一時停止（利用枠切れ / 鍵待ち）・利用枠切れが上限回数続いた | ADR-0043 の時点で既知 | `docs/adr/0043-…:59`「下見の表示は別票」 |

★**画面が「次はこれ」と見せた票を、`dispatch` が飛ばす。**
これは「取得できていない」を「0 件」と混ぜないのと同じ型の問題で、
画面が**確かめていないこと**（飛ばすかどうかの判定）を**確かめたかのように**見せている。

`core` の中にも「次」が 2 つあった: 下見の `ticket_next()`（生の `kb next`）と、
PM の `_pm_pick_next()`（先行条件だけ見る）。PM 側も一時停止は見ていなかったので、
`dispatch` が飛ばす票を `picked_next` として提案していた。

## 決定

1. 「実際に回る票」を決める口を **core に 1 つだけ**置く: `pm_pick_next(kb next の返り, pj)`。
   非公開だった `_pm_pick_next` を公開名に変え、一時停止も見るように広げる。
   **下見（`ticket_next`）も PM（`pm_status` / `pm_decide`）もこの 1 か所を通る。**
2. 飛ばすのは、**板と run の記録だけで確かめられる** 2 つに限る。
   - 未完了の先行票がある → 判定は `pm_unmet_deps`（ADR-0078 と同じ 1 か所）
   - 解除前の一時停止 / 利用枠切れが続いた → 正本は `kb resumable --json`（ADR-0043 / ADR-0046）。
     解除時刻と回数の規則は `kb` の `resume_plan` が持ち、`core` にも `dispatch` にも書き写さない。
     `core` は `ready` / `hits_exceeded` の**結果**を読むだけ（`dispatch` の 2 条件と同じ）。
3. 配車のときの環境で決まるもの（PJ の `project.yml`・Pull worker・プールの空き）は**下見では確かめない**。
   確かめていないことは、そう分かる文言を画面に出す（黙って「大丈夫」に見せない）。
4. 下見の返りは「票 1 件」から「**選び直した結果 + なぜそうなったか**」にする:
   `next` / `reason` / `kb_next`（薄い `kb next` が返した生の id）/ `skipped_by_dependency` / `skipped_by_pause`。
   `next` キーは残すので既存の呼び手は壊れない。
5. 理由の語彙は **PM と共通**にする（ADR-0074 決定 5 の表）。足すのは `blocked_by_pause` の 1 語だけで、
   下見のために別の語彙を作らない。`blocked_by_pause` は「解除前の一時停止の票しか残っていない」＝
   時刻が来れば機械（`dispatch --resume-paused` の timer）が片付ける、という意味で、
   人が先に片付ける `blocked_by_dependency` とも、人の一時停止指示（`paused`）とも別の値にする。
6. `kb next` / `kb resumable` / `dispatch` は**変えない**（ADR-0077 / ADR-0078 / #573 が正本）。

## 理由

- 下見と本番が別の規則で選んでいる限り、**どちらを直しても食い違いは残る**。
  ADR-0043 が「別票」と書いて先送りした食い違いが、#573 で 2 例目として同じ形で再発した。
  片方ずつ潰すのをやめ、**選ぶ口を 1 つにする**（判定の置き場を増やさない = ADR-0015 / ADR-0074 決定 1）。
- 「なぜこれが次なのか」が読めることが、この画面の主役（ADR-0074 決定 5 の判断ログの精神）。
  飛ばした票を黙って消すと、**利用者から見れば下見が嘘をついたのと同じ**になる。
- 一時停止を PM も見るようになるのは副作用ではなく修正。PM は `dispatch` が飛ばす票を
  「次はこれ」と提案しなくなる（`picked_next` の意味が「実際に回る票」で揃う）。

## 結果（トレードオフ）

- `pm_status` は 5 秒ごとに読まれ、そこに `kb resumable` の呼び出しが 1 回増える
  （todo 件数ぶんの `state.json` 読み）。遅くなったら候補選びを SQL 1 回に寄せる余地はあるが、本票ではやらない。
- `kb resumable` が引けなければ例外を上へ出す。下見は `ApiError`、PM は `board.readable = false`
  （「候補なし」に倒さない）。確かめられなかったことを、確かめた結論と混ぜない。
- `kb resumable` は `kanban.db` を作る。`pm_status` は「DB があるときだけ `kb` を呼ぶ」既存の分岐の中から呼ぶ
  （副作用なしの約束を守る）。
- 下見と `dispatch` の一致は、**同じ板に両方を当てて選んだ id を突き合わせる**テストで守る
  （`console/tests/test_next_preview.py`。VM も claude も使わない）。
- 3 つ目の食い違い（プールの空き・worker）は残る。これは板と run の記録からは確かめられないので、
  下見に載せるなら別の材料が要る。いまは「確かめていない」と書くところまでにする。
