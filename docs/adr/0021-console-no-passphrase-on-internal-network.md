# ADR-0021: コンソールは内側の網のアドレスには合言葉なしで bind できる

日付: 2026-09-07 / 状態: 採用（0017 の 5 を緩める） / 決定者: メンテナ（「internal の場合、多分 localnet だと思うので、認証は不要にしたい」）

## 状況
- ADR-0017 で、コンソールは合言葉（`CONSOLE_TOKEN`）が無い限り 127.0.0.1 以外へ bind しないと決めた。制御系 LXC は `10.77.0.3`（テナントの sbnet）に bind し、到達は tailnet の subnet router 経由だけ
- 実運用では、貸出先の運転員が最初に `/?token=` を踏む手間と、合言葉の受け渡し（ctl.env の中身を見せる）が毎回発生した。網の境界は既に tailnet の ACL と Proxmox の firewall が守っており、合言葉は「念のため」の二重化だった
- 合言葉があってもなくても、コンソールが状態を変える経路は既存 CLI だけ（ADR-0013）で、変わらない

## 決定
- bind 先が **内側の網のアドレス**（ループバック、10/8・172.16/12・192.168/16、tailnet の 100.64/10、リンクローカル、ULA。Python の `ipaddress` で `is_global` でないもの）なら、合言葉なしで起動できる
- **0.0.0.0 / ::（全インターフェース）とグローバルアドレス**は従来どおり合言葉が必須（無ければ起動を拒む）。ホスト名は判断できないので安全側（必須）
- `CONSOLE_TOKEN` を設定すれば、どのアドレスでも認証がかかる（cookie / Bearer / `?token=`）。任意の二重化として残す
- `install.sh --systemd` も同じ判定を使う。テナントの構築スクリプトが生成する合言葉は、貸出先が不要なら ctl.env から外してよい

## 理由
- 「無認証で外に出さない」（ADR-0013）の「外」は、グローバルに到達できる場所のこと。tailnet と firewall の内側は、CLI（`kb` / `sandbox`）に ssh で入れる人と同じ範囲であり、コンソールにだけ合言葉を求めても守れるものが増えない
- 判定を IP の種別に固定することで、「どの網が内側か」の運用判断をコンソールに持ち込まない。全インターフェース bind を必須側に残すのは、ホストに公開インターフェースがある場合の事故を避けるため

## 結果（トレードオフ）
- 良い: 貸出先は `http://ctl.<tenant>.sb.internal:8765/` をそのまま開ける。合言葉の受け渡しが要らない
- 悪い: tailnet の中に入れる端末はすべてコンソールを操作できる。tailnet の ACL（誰がテナントの網に入れるか）が唯一の境界になる。端末単位で絞りたいテナントは `CONSOLE_TOKEN` を置く
- 実測（2026-09-07）: `main` テナントの制御系（`10.77.0.3`）で `CONSOLE_TOKEN` を外して再起動し、合言葉なしで 200 を確認。unittest に bind 判定のテストを追加
