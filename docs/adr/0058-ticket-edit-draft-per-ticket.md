# ADR 0058: チケット詳細の項目編集は、チケット単位の下書き（sessionStorage）で守る

- 状態: Accepted
- 日付: 2026-09-10

## 状況

チケット詳細（`console/static/app.js` の `viewTicket()`）の「項目を直す」（`kb set`。種別・PR・メモの 3 欄）は、
入力値を DOM にしか持っていなかった。この画面は 2 つの経路で作り直される。

- `route()` は hash が変わるたび `viewTicket()` を呼び、`render()` が `main.innerHTML` を丸ごと差し替える。
  メモを打ちかけたままパンくずの「ボード」へ寄り道して戻る・ブラウザーの戻る・再読み込みの、どれでも入力が消える。
- `viewTicket()` は末尾で自分自身を 5 秒ごとに呼び直す（`schedule`）。抑止は `editing()`（フォーカスが入力欄にあるか）だけなので、
  **打った後に欄からフォーカスを外して 5 秒待つ**と、同じ画面に留まっていてもサーバー値で描き直されて消える。

どちらも離脱の警告は出ないので、消えたことに気づくのは書き直しの段になってからになる。
起票画面には同じ問題への答えが既にある（ADR-0019 / チケット 219。`DRAFT_KEY = 'intake-draft'` と `draftRead` 系）が、
そちらは画面が 1 枚しかないので入れ物を分ける必要がなかった。チケット詳細は ID ごとに別のフォームなので、そのままは使えない。

「離脱時に破棄を選べるようにする」案（`beforeunload`）は採れない。ブラウザー標準のダイアログは `console/UX.md` の文言規則の外に出るうえ、
`console/tests/test_console.py` が `beforeunload` を全体で禁止している。UX.md の起票の行も「離脱の警告は出さない。保持で守る」と約束している。

## 決定

1. **保持で守る。離脱の警告は出さない。** 起票の下書きと同じ約束を、チケット詳細の 3 欄にも広げる。
   明示的に捨てたいときのために「下書きを捨てる」を出し、トーストの「元に戻す」で書き戻せるようにする（可逆なので確認は出さない）。
2. **入れ物はチケット単位。** 鍵は `ticket-draft` 1 本で、中身は `{ "<チケット番号>": { v, base, at } }`。
   別のチケットのフォームに他の ID の値が混ざらないことを、置き場の形で保証する。保存先は起票と同じ `sessionStorage`
   （同じタブの往復・戻る・再読み込みで残り、タブを閉じれば消える。`localStorage` だと別タブ同士で上書きし合う）。
3. **持つのは「サーバー値と違う欄」だけ。** 3 欄すべてが記録と一致したら項目ごと消す。打った内容を打ち消した後に下書きが残らない。
   入れ物は 20 件でうち止め、あふれたら古い順（`at`）に捨てる。`sessionStorage` が一杯なら黙って諦める（保存操作そのものは止めない）。
4. **描画は下書き優先。** 3 欄の `value` / `selected` は「下書きにあればそれ、無ければサーバー値」で描く。
   これで画面の往復も 5 秒の自動更新も入力を消さない。見出しの札とメモのパネルは記録の値のまま出す（記録の正本を隠さない）。
5. **記録の側が動いたら黙って上書きしない。** 下書きを作った時点の記録（`base`）を焼き付けておき、
   今のサーバー値と違う欄があれば、その項目名と今の記録の値を欄の下に警告で 1 行出す。入力は消さず、気づける状態にとどめる。
6. **捨てるのは保存が通った後だけ。** `actions['set']` は `await api(...)` が成功してから下書きを消す。
   通信やコマンドが失敗すれば例外で抜けるので入力は残り、直して送り直せる（起票側と同じ並び）。

対象は「項目を直す」の 3 欄だけで、実行の詳細設定（`run-wf` / `run-keep` / `run-resume`）と本文の編集は含めない。
サーバー側（`console/lib/core.py`・`kb`）は変えない。入力が消えるのは画面の中で完結した問題で、記録は最初から無事だった。

## 結果

- メモを書きかけたまま過去の実行や看板を見に行って戻れる。申し送りの書き直しが要らなくなる。
- 状態同期（`kb sync`）や runner が記録側のメモを動かしても、未保存の入力が黙って消えることはなく、ずれたことは画面で分かる。
  `sync` 自体の挙動は変えない（runner による保存済み `note` の上書きは別の問題として扱う。ADR-0048）。
- 下書きはブラウザーの中だけにあるので、別のタブ・別の端末では見えない。タブを閉じれば消える。
- JS を動かす基盤が CI に無いので、約束の検査は `console/tests/test_console.py` のソース検査で行う
  （保存先と鍵の形・3 欄の対応表・下書き優先の描画・`await api` の後で捨てること・`beforeunload` を使わないこと）。
