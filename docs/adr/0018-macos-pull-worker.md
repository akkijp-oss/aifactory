# ADR-0018: macOSの実行先はGo製のpull workerとして追加する

日付: 2026-09-07 / 状態: 採用、段階的に実装

## 決定

- 制御系はProxmox上に残し、Mac上のワーカーがHTTPSで操作を取得する。workflowの分岐とチケット台帳は制御系に集約する。
- Macへ配布するワーカーはGo標準ライブラリのみの単一バイナリとする。配布先にPythonやGoの実行環境を要求しない。macOS VMを動かすTartは別の依存として明示する。
- ワーカー用HTTPS受信サービスはconsoleと認証を分ける。初期は管理者が制御系のローカルCLIで登録し、ワーカーごとのトークンを管理経路で配布する。
- 操作とログ受領は制御系のSQLiteに永続化する。Macは排他ロックと永続ジャーナルを持ち、結果不明の操作を自動再実行しない。uncertainの予約は停止確認後の管理操作まで解除しない。
- 任意コマンドは管理者が固定したTartゲスト内でのみ実行する。操作payloadからMacホストのシェルやVMを選択させない。
- 外部Macへ向けた制御系の新規接続を許可せず、ワーカー受信口だけを追加する。

## 理由

ユーザーが複数組織への貸出とMacのシームレスな登録を見据えてpull方式を選択し、Mac側の単一バイナリ配布を希望した。既存のPython制御系を維持しつつ、Mac側の導入・更新と実行環境を単純にする。

## 実装段階と制約

第一段階は `workers/` の認証・操作取得・heartbeat・ログ/結果返送と `probe` / `guest-exec`。この段階は検証基盤であり、既存runnerへの統合やタスクごとのVM初期化はまだない。通常のチケットをmacOSへ自動配車する前に、VMのprepare/reset/release、成果物転送、OS別backendを実装する。

Macの常駐は当面ユーザーのLaunchAgent。ログイン前の自動稼働、サービス専用アカウント、GUIテスト、ゲストのネットワーク隔離は実機検証を伴う後続工程。現在の診断基盤を本番用の隔離プールと同一視しない。
