# ADR 0065: モデルの設定は console が作業ツリーの `workflow/kit/` を直接書き、工程単位の `model` を新設する

- 状態: Accepted
- 日付: 2026-09-11

## 状況

設定画面の工程詳細（`#/config/workflow/<name>/<stepId>`、ADR-0062 / チケット 415）は実効モデルを**表示するだけ**だった。
モデルを変えたい運転員は制御系に入って `workflow/kit/routes.env` を手で直すしかなく、配備先では実際にそうなっている
（2026-09-10 に別のメンテナが `MODEL_judgment` を暫定変更し、コメント行で理由と戻し方を残した）。手で直すと、
変更前後の実効値・影響する工程・実行中の run への影響が誰にも見えないまま次の run に効く。

決めるべきことが 3 つあった。

1. **どこに何を書くか**。`resolve_model` が読むのは `routes.env`（クラス単位の共通設定）と工程の `model_class` だけで、
   「同じクラスの他の工程を動かさずに、この工程だけ別のモデルにする」を表す場所が定義に無い
   （`grep model_class workflow/kit/workflows/*.yml` は 0 件で、`model_class` は使われてもいなかった）。
2. **書き先がリポジトリの一部であること**。既存の書き込み（ADR-0052 の `project_write`）の書き先は
   `$AIFACTORY_WORKSPACE/projects/`（git 追跡外の運用データ）で、「運用データは書ける・定義は読むだけ」という
   ADR-0016 系の区分に収まっていた。`workflow/kit/` はリポジトリの一部で、この区分の外にある。
3. **競合の検知**。ファイルの版を鍵にした排他の前例が無い（`Conflict` は JobStore の二重起動用、`.bak-` は退避）。

## 決定

1. **工程単位の `model`（モデル名の直接指定）を schema と `resolve_model` に足す**。優先順は
   `CLAUDE_MODEL`（環境）> 工程の `model` > `MODEL_<クラス>` > `MODEL_default` で、`model_from` に `"step"` を入れる。
   `model_class` は残す（クラスごと替えたいときの手段）。クラスの上書きだけでは「1 工程だけ動かす」が表現できず、
   共通経路を触れば同じクラスの全工程が道連れになる。
2. **console は制御系の作業ツリーの `workflow/kit/` を直接書く。git commit はしない**。runner（`Run.__init__`）は
   作業ツリーの `KIT/routes.env` と `kit/workflows/*.yml` をそのまま読むので、ここを書かない限り実効値は変わらない。
   workspace 側に写しを置いて runner の読み先を変える案は却下した（ADR-0062 が 1 か所に集めた「解決規則」を
   「どのファイルを読むか」の軸で二重化することになり、配備先の実態とも合わなくなる）。
   代わりに危険は隠さず見せる: 保存前の下見（変更前後の実効値・影響する全工程・動いている run・反映時点）、
   `.bak-<時刻>` への退避、保存後の `git status` の当該行、「commit していないので `git pull` で戻ることがある」旨の表示、
   `$AIFACTORY_WORKSPACE/logs/config-changes.jsonl`（git 追跡外）への 1 行の記録。
3. **実効値は必ず `lib/aifactory_workflow.py` を呼び直して作る**（ADR-0062 の継承）。閲覧・下見・保存後の再表示は
   どれも `resolve_model` の答えで、画面にも保存処理にも式を写さない。影響する工程は
   「全 workflow × 全 agent 工程の実効値を前後で解き直して、変わったものを挙げる」で出す。
   モデル名 → 鍵の系統（`token_family`）も runner から lib へ移し、runner は委譲だけにした。
4. **書けるのは許可した設定だけ**。`routes.env` は `MODEL_<クラス>` と `MODEL_default` のみ、工程は `model` と
   `model_class` のみ。値はモデル名の形（`^[A-Za-z0-9._-]{1,64}$`）と、鍵の系統（fable / opus / sonnet / haiku）が
   分かることを見る。系統の鍵が鍵プールに無い場合は**保存を止めず警告に留める**（「指定できる」と「使えるか未検証」は別）。
   モデル名の固定の一覧は持たない（候補は今この設定で使われている値から作り、自由入力も受ける）。
   任意のシェル・任意のファイル編集の口にはしない。
5. **書き方は行単位の外科手術 + 書く前の突き合わせ**。pyyaml で読み書きするとコメント・並び・引用が失われるので
   （ADR-0052 と同じ理由）、当該 1 行だけを差し替え・追加・削除する。書く前に編集後の本文を読み直し、
   (i) schema に適合する (ii) 当該工程の当該キー以外が変わっていない、を確かめる。どちらか落ちたら何も書かない。
   順番は 検証 → 退避 → 同じディレクトリの一時ファイル → `os.replace`。
6. **競合は内容のハッシュで検知する**。`GET /api/config` が対象ファイルの `sha256` を返し、保存は
   `base_sha256` を必須にする。`_flock()` の中で読み直し、一致しなければ**何も書かずに 409** で返す
   （他者の編集・外部の編集を上書きしない）。既定は下見（`dry_run` は既定 true。JSON の `false` を明示したときだけ書く。
   `sync_apply` と同じ型）。保存に失敗したとき、画面は入力を消さない。
7. **実行中の run は触らない**。`routes.env` も yml も runner が起動時に 1 回読むだけなので、保存しても走っている run の
   モデルは変わらない。新しい run と `--resume` / `--from`（別プロセス）は起動時点の値を読む。画面はこれを
   「次に始める run から効きます」と出し、走っている run の一覧を下見に載せる。配車はしない。
8. **code 工程・鍵・トークンは対象外**。`role` の無い工程はモデルを使わないので編集の入口を出さない。

## 結果

- 運転員は工程詳細から (a) この工程のモデル (b) この工程のクラス (c) 共通の経路 を変えられる。(a)(b) には「継承へ戻す」
  （キーを消す）が付く。(c) は危険色で、影響する工程の件数を本文に入れる。
- 元に戻す手段は、退避した控え（`.bak-<時刻>`）の内容を入れ直すか、git の差分を捨てること。変更の記録は
  `logs/config-changes.jsonl` と画面の「最近の変更」に残る。
- 検査は runner と console が同じ期待表（`workflow/tests/model_fixture.py`）を読む。書き込みのテストは
  kit の一時コピーに対して行い、リポジトリ本体の `workflow/kit/` を書き換えない。
- 残る弱さ: **commit しないので、制御系で `git pull` すると設定が戻る**。配備先の checkout とこの checkout が
  同じかどうかは、ADR-0062 と同じくここでは確かめられない。「戻ったこと」に気づく仕組み（配備との差分の検知）は
  この決定には含めない。
- `CLAUDE_MODEL` は console からは読めない（ADR-0062 決定4）。画面は優先順の一番上として説明するだけで、
  実際に使われた値は統計画面で見る。
